## 人工复核步骤

使用明确的隔离候选和独立 profile；日常安装无需改动。详细界面步骤见[多仓需求验收说明](fork-orca34-multi-repo-v2-acceptance.md)，交付命令及回执恢复见[本地交付说明](fork-orca34-local-delivery.md)。

1. 打开需求管理，新建名称和描述，选择两个测试仓库，保留默认目录与分支；确认根目录及两个成员正常。
2. 保存仓库组合、命名模板、Agent 与规则，关闭重开后新建；确认默认值复用，但描述和附件不串到新需求。
3. 搜索、改名、归档再恢复；添加第三仓库，清理后重新加入。放入未提交文件再检查清理，应明确阻止。
4. 粘贴富文本、从 Finder 复制图片和文件、从 Preview 复制图片像素，再上传附件；创建后打开副本，重开确认仍在。测试超大文件被拒绝后可继续正常上传。
5. 选择实际已登录的 Cursor，给出只改测试仓库的简短任务；观察两个成员的输出，再使用详情的重启根 Agent，确认保存参数保留。
6. Codex 插件使用已经安装的 `插件名称@市场名称`；在需求中启用/停用并观察实际会话。多仓可写任务使用 `workspace-write`，不要把 `read-only` 与额外可写 Git 元数据目录混用。已有需求详情不能编辑保存的启动参数，改变参数需新建需求。
7. 安装复核只使用隔离目标和 profile，按交付文档准备、安装、健康检查、正常重开及配套回退；每步保存回执，不手工覆盖回执目录或跳过备份。
