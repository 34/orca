# Orca 34 多仓库需求管理：第二轮验收

这份文档对应第二轮的创建默认值、需求管理、成员增删、富文本附件及工作区规则预设。上一轮安装的 candidate8 不包含这些新增界面；验收应使用本轮源代码启动的开发实例。它们不是安装包发布或合并授权。

## 验收环境

- 使用独立的开发配置及临时 Git 仓库，避免业务仓库受到测试影响。
- 本轮后台实例设置 `ORCA_BACKGROUND_LAUNCH=1`，不抢焦点，不主动显示测试窗口。
- Claude 真实 CLI 验证按用户要求跳过；Pi 不在本轮接入范围。
- 根 Agent 目前延续已验证的 Codex/Claude 入口。Cursor 的多仓库专用权限与真实会话验证仍是后续工作，不能以普通 Cursor 能启动代替。
- Computer use 是本轮要求的最终操作验收。当前工具初始化返回 `Sky Computer Use native pipe startup failed`，重置会话后再次初始化仍失败。后台 CDP 验证单独记录，不能替代这项验收。

## 一、默认创建流程

1. 打开侧栏项目标题旁的双文件夹按钮「需求管理」。
2. 点击「新建需求」。
3. 填写需求名称和任务说明，选择至少两个本机 Git 仓库。
4. 保持「高级选项与工作区预设」收起，点击「确认创建需求工作区」。
5. 等待成员就绪，界面应自动进入根工作区。

通过条件：除名称、描述和仓库选择外，无需逐个填写分支、成员目录或根目录。成员目录采用仓库目录名；同名目录自动加数字后缀。起始引用优先使用仓库已有配置，否则使用 HEAD。分支和根目录包含唯一后缀。默认父目录不存在时自动准备；如果系统的工作区基础目录无效，明确显示错误，允许在高级选项中选择其他本机目录。

「预览创建计划」仍可选用；直接创建也会在主进程验证仓库、路径、引用和分支冲突。

## 二、保存配置并复用

1. 新建需求，展开高级选项。
2. 将分支格式改为 `feature/{name}-{id}`，目录格式改为 `request-{name}-{id}`。
3. 填写工作区规则及自定义 Agent 指令，选择根 Agent（可选）。
4. 点击「保存为新需求的默认配置」。
5. 如需改变父目录，填写已有的绝对目录并点击「记住此目录」，或点击「使用默认目录」。
6. 关闭并重新打开新建界面；重启开发实例后再检查一次。

通过条件：模板、Agent、规则、Skills 引用、插件指引与父目录保留在当前 Orca 配置内；新需求自动带入。需求描述、附件和仓库选择不会被当作所有后续需求的默认上下文。模板使用 `{name}` 和 `{id}`，保存时要求保留 `{id}`。修改模板或需求名称会更新仍使用自动值的目录和分支，手动覆盖的值保持原样。

## 三、需求管理面板

1. 点击「需求管理」。
2. 用需求名称、成员目录名或分支名称搜索。
3. 切换「进行中」「待处理」「已归档」「全部」。
4. 点击需求名称进入详情，使用「返回需求列表」返回。
5. 对有效且未归档的根工作区使用列表中的「打开根工作区」。
6. 在详情修改显示名称并归档，检查归档筛选及新显示名称的搜索。

通过条件：当前配置的需求可检索，新建需求优先显示；显示成员就绪数量。待处理筛选包含创建错误、Agent 启动错误及尚待恢复的成员变更。归档保留文件和分支；清理完成的需求仍可在「全部」查到历史记录。

## 四、创建后添加、移除与重新加入仓库

### 添加

1. 创建 api + web 的需求，等待两个成员都就绪。
2. 在详情展开「添加仓库」，选择 admin。
3. 点击「添加仓库」，阅读停止根会话的提示并确认。
4. 等待 admin 就绪，打开成员目录，检查分支。
5. 在根目录检查 TASK.md 和 `.orca-multi-repo.json` 已包含新增成员。

通过条件：api/web 的已有文件和分支不变。根会话在权限变更前停止，不自动重复提交原始需求。下次手动启动 Agent 时重新核对现有成员的 Git 元数据目录权限。

### 安全移除

1. 点击「检查清理影响」。
2. 找到 admin，确认分支保留及文件检查结果。
3. 点击该成员的清理按钮并确认。
4. 检查目录已移除，Git 分支仍存在，api/web 仍可使用。
5. 另外在一个成员中创建未跟踪文件，再刷新检查。

通过条件：未提交、未跟踪、忽略文件或检查不完整时禁止清理。移除后剩余成员仍可启动 Agent；已移除成员的外部 Git 元数据不再加入新会话的写权限。

### 重新加入

1. 将已清理的 admin 再次从「添加仓库」加入。
2. 检查使用新的唯一分支名，旧分支保留。
3. 等待就绪，确认当前成员列表只有一个 admin，不重复登记。

通过条件：历史创建计划保留在需求记录中，当前计划对应新工作树。TASK.md 的仓库清单是创建计划；规则要求 Agent 只操作当前仍存在的成员目录。

### 变更恢复

自动化测试应覆盖追加计划持久化之后、根上下文刷新中间被中断的情况。恢复后每个文件允许处于旧或新一代完整内容；用户改写过的 TASK.md、AGENTS.md 或附件必须保留并报错，不能覆盖。原始已登记成员的计划不能被普通重试改写。

## 五、富文本与图片、文件上下文

1. 输入段落并使用工具栏加粗、标题、列表、链接及代码格式。
2. 粘贴截图，或从文件管理器拖入图片和文件；也可点击「上传上下文文件」。
3. 上传一张 PNG 和一个文本附件，观察图片及附件名称。
4. 在创建前移除其中一个附件，确认引用和附件列表同步移除。
5. 再上传附件并创建需求。
6. 在详情查看富文本、图片及附件按钮；附件按钮应在文件管理器定位任务目录内的副本。
7. 检查 TASK.md 中的相对引用和根目录的 `context-<uuid>.<扩展名>` 文件。

通过条件：格式保存为 Markdown，图片及任意文件作为独立文件复制到任务根目录，Agent 能按 TASK.md 中的路径读取。上传错误可见且不会提交半读完的附件。最多 20 个文件，每个最多 10 MB，总计最多 20 MB。附件文件名不会成为任意文件路径。修改过的附件不会被后续清理静默删除。

## 六、工作区 Agent、Skills 与插件预设

1. 在高级选项中填写 AGENTS.md 规则及自定义 Agent 指令。
2. 点击「发现已安装的 Skills 和插件」。
3. 搜索并勾选与需求有关的 Skill，例如前端规则、测试流程或仓库已有技能。
4. 查看已安装插件的实际状态，按需填写插件使用指引。
5. 保存默认配置，创建需求后检查根 AGENTS.md。

通过条件：根 AGENTS.md 包含规则、Agent 指令、Skill 文件引用与插件指引；成员仓库原有 AGENTS.md/CLAUDE.md 保留。插件列表展示真实安装状态。

功能边界：Skill 选择生成可读取的规则引用，不复制或重新安装 Skill；插件沿用 Orca 已有安装、授权与启用设置，此处指引不代表插件按工作区独立启用。自定义 Agent 指令也不改变全局模型、账号或 Agent 可执行文件。若需要独立的工作区插件隔离或自定义 Agent 启动器，需要进一步扩展现有系统，不能将当前的上下文预设视为已经实现这些能力。
